# Department OS

**Turn uncertainty into a tested business model.**

Department OS is a creative research, business-model discovery, validation, and product-development operating system. It exists to move ideas from paper to practice: from a signal or a hunch, through evidence-backed problem discovery, to a tested prototype and a real decision.

## Philosophy

> From paper to practice.

Department OS does not reward activity. It rewards evidence, decisions, and things that got built and tested.

## What it does

Department OS is organized into product modules, each answering a distinct question:

| Module | Primary question |
|---|---|
| [Signal Foundry](docs/modules.md#signal-foundry) | What is emerging that deserves attention? |
| [Problem Department](docs/modules.md#problem-department) | What do people genuinely need, and where is the unresolved demand? |
| [Prototype Department](docs/modules.md#prototype-department) | What is the smallest credible thing we can build to test this opportunity? |
| [Creative Practice Engine](docs/modules.md#creative-practice-engine) | How does this collection of projects become a coherent creative practice? |

Alongside the product modules sits the public lab, [Mandate to Build](docs/modules.md#mandate-to-build), and its community leg, [Skool](docs/modules.md#skool-community). A later module, [Patent Reinvention](docs/modules.md#patent-reinvention-later), is documented but explicitly out of scope for early implementation.

All of this runs on **Department OS Core** — the shared operating environment for dashboards, agent observability, the evidence ledger, the knowledge graph, and durable workflow state. See [docs/architecture.md](docs/architecture.md).
